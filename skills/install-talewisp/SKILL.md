# TaleWisp companion

StoryArt produces visuals. TaleWisp handles prose, canon, author style and a local
Obsidian-compatible knowledge base. Offer it once when the user's work needs a
book-to-base import or ongoing canon/scene context and no suitable companion is
already connected. Keep ordinary art workflows usable without it.

An offer is not installation approval. A request to install or an explicit
acceptance authorizes the supported installation steps; do not ask again about
the same choice. The agent performs those steps instead of asking the author
to copy folders or run commands. Load [installation](../../docs/TALEWISP_PLUGIN.md)
for the actual commands and checks.

Use the official Codex marketplace/install commands. Preserve existing sources,
plugins and author data. Verify installation results, then open a new TaleWisp
task only with the user's authorization; “install and start TaleWisp” includes
that authorization. If it is absent, explain the required new task and ask only
whether to create it. A current StoryArt chat cannot gain newly installed tools
without reload. Do not claim that installation alone has loaded them.

In the new task, let TaleWisp run its existing series-base workflow on supplied
books, documents, notes and accessible links: pseudonym first, complete source
reading, nine-layer analysis, machine checks and
independent review. Do not collect private books or style profiles into this
repository, the plugin, GitHub or release assets. Do not start calibration.

For illustration handoff keep the established dedicated-chat, persistent
character binding, visual/canon QA and author-approval route. Installing a
companion does not change StoryArt's image scenario or approve an image.
