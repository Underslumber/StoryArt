# Проектный оркестратор StoryArt

С 2026-09-09 применяйте [EFFICIENT_WORKFLOW.md](EFFICIENT_WORKFLOW.md) для выбора
моделей, бюджетов и числа реальных субагентов. Роли ниже — логические обязанности,
а не обязательная цепочка из шести отдельных агентов. `storyart_orchestrator.py`
создаёт и проверяет handoff/state; он не запускает модели и не обеспечивает
технический scheduler. Реальные вызовы выполняет основной агент через native spawn
с явными model/effort и ограниченным контекстом. Для простых действий отдельный
subagent не нужен. Адаптеры пересобираются только при отсутствии или изменении источников.

Оркестратор работает только внутри StoryArt. Он не устанавливает глобальные навыки, не
запускает отдельный сервер и не заменяет существующие менеджеры проекта.

## Что он разделяет

Основной агент остаётся единственной точкой общения с пользователем и владельцем
`EXECUTION_GUARD.json`. Для объёмной задачи он может передавать ограниченные подзадачи ролям:

- `STYLE_LIBRARIAN` — полный просмотр стиля и выбор референсов;
- `IDENTITY_CURATOR` — каноническая идентичность персонажа;
- `CALL_PLANNER` — один точный промпт и фактические вложения;
- `GENERATOR_OPERATOR` — логическая обязанность основного агента: один
  подготовленный вызов генератора;
- `VISUAL_QA` — независимые проверки результата;
- `REGISTRAR` — логическая обязанность основного агента: архивирование и запись
  через существующие менеджеры.

Субагенты используют общую файловую систему, поэтому изоляция обеспечивается явными
контрактами чтения и записи. Исследовательские роли остаются read-only.
`GENERATOR_OPERATOR` и `REGISTRAR` не передаются субагенту в обычной production-работе:
основной агент выполняет их последовательно и не создаёт для них handoff.

## Состояние запроса

Любое подтверждённое дополнение профиля персонажа должно автоматически
применяться в последующих сценах. Общий механизм `confirm-profile` сохраняет
подтверждённую версию: данные любой вложенности, основные визуальные
ресурсы и альтернативы. Агент выполняет подтверждение после решения пользователя;
повторное подтверждение и ручное редактирование файлов пользователем не нужны.

Подготовка читает действующую подтверждённую версию, включает её данные
в исполняемый промпт и применимые основные изображения — в фактические вложения.
Явное изменение для отдельной сцены не меняет постоянный профиль. Черновые правки
не заменяют подтверждённую версию. Версия и содержимое связываются с точным вызовом:
устаревший план пересобирается, потерянные данные или подменённые изображения
не допускаются к запуску.

Обновление выполняет агент после подтверждения пользователем. `expected-revision`
берётся из текущего resolver, `operation-id` остаётся тем же при повторе операции,
а `confirmation-quote` содержит фактическое подтверждение. Пример вызова:

```powershell
python tools\style_pack_manager.py confirm-profile --workspace . --style-name "<STYLE>" --character-id CHAR_NNN --patch-file "<confirmed-patch.json>" --expected-revision <N> --operation-id "<stable-operation-id>" --confirmation-quote "<user confirmation>"
```

Для подтверждения полного отредактированного профиля используется
`--candidate-yaml` вместо `--patch-file`: это полная замена фактов, поэтому
пропущенные поля удаляются. Patch объединяет указанные поля с текущими.
Числа, логические значения, ноль, false и null сохраняются как данные; null
не означает удаление поля. `--active-asset ROLE=PATH` задаёт
подтверждённый основной ресурс; `--alternative-only` сохраняет вариант без смены
основного. Поддерживаемые роли: `WARDROBE`, `ACCESSORY`, `FACE_VARIANT`,
`BODY_VARIANT`. В `prepare-generation` временное исключение роли задаётся через
`--suppress-profile-default ROLE`; постоянный профиль при этом сохраняется.

`ORCHESTRATION_STATE.json` хранится рядом с активным `EXECUTION_GUARD.json`. Отдельные задания
лежат в `ORCHESTRATION_HANDOFFS`. Субагенты не редактируют эти файлы: результат записывает
основной оркестратор.

Для `CHARACTER_BASE` указывай `--character-age-group CHILD|ADULT`. Детская база
фиксирует возрастную группу и тип закрытой одежды в `REFERENCE_PLAN.json` и
`character_kit`: мальчик — непрозрачная возрастная футболка и шорты, девочка —
непрозрачная возрастная футболка и юбка. Все пять stage-промптов сохраняют
полный комплект; в крупном плане лица видна футболка, а нижняя одежда может
быть вне кадра.
`SAFE_COVERAGE`, `CLOTHING_TOPOLOGY` и `CLOTHING` проверяются отдельно. Детские
вызовы запрещают взрослый купальник, topology override и adult anthropometry.
Если в активном guard уже был другой обязательный deliverable, новый scope можно
добавить только явным `checkpoint --event SCOPE_CHANGE --user-approved-scope-change
--add-required-stage <ID>`; операция блокируется при ACTIVE или UNKNOWN попытке.

Для новой `CHARACTER_BASE` два выбранных face-crop по умолчанию остаются
`STYLE_SEED`. Используй `--new-face-reference-purpose USER_IDENTITY_INTENT` только
когда текущая инструкция автора прямо задаёт эти источники как намерение к
внешности, и приложи её текст через `--new-face-reference-purpose-evidence`.
Такой режим принимает только два отличных друг от друга зарегистрированных
FACE источника с проверенными метками пола, совпадающими с текущей целью и
точными хешами. Их семантическая роль — `FACE`, физические слоты сохраняются;
независимый `STYLE` источник обязателен. Режим не устанавливает постоянную
личность персонажа и не меняет проверки существующих персонажей или `SCENE`.

Команда ниже нужна только при фактическом делегировании субагенту. При работе
root без субагентов пропускай init, status и handoff: достаточно активного guard.
При делегировании роли получают один контракт:

```powershell
python tools\storyart_orchestrator.py init `
  --state "<request-dir>\ORCHESTRATION_STATE.json" `
  --guard "<request-dir>\EXECUTION_GUARD.json"
```

## Внутренние навыки стилей

Адаптер — необязательный индекс маршрутизации. Если профиль и пути источников
уже известны, пропускай его просмотр и сборку. Builder нужен только для реально
используемого отсутствующего или устаревшего адаптера; передавай точное имя
стиля, чтобы обновить только его адаптер и строку индекса:

```powershell
python tools\storyart_orchestrator.py build-style-skills --style-name "<selected STYLE>"
```

Полную пересборку и проверку всех адаптеров выполняй только при обслуживании
локального набора стилей, а не при старте каждого запроса.

Адаптер содержит только имя, локальные пути и правила загрузки свежего `style-context`.
Изображения в него не копируются. Он не устанавливается в профиль Codex и не заменяет style
pack как источник истины.

## Порядок выполнения

1. Основной агент фиксирует `EXECUTION_GUARD`.
2. Инициализирует состояние оркестратора только при фактическом делегировании.
3. Использует уже известные пути профиля и источников. Если нужен адаптер,
   читает выбранный; builder запускает лишь для отсутствующего/устаревшего.
4. Делегирует только действительно необходимую отдельную работу; обычный
   запрос выполняет root без субагентов.
5. Последовательно выполняет планирование вызова, root-held генерацию, QA и
   root-held регистрацию.
6. Проверяет статус только реально созданных handoff и закрывает guard только
   после всех обязательных стадий.

Если нативные субагенты недоступны, основной агент выполняет те же роли последовательно. Это
сохраняет контракты и не превращает наличие субагентов в обязательную внешнюю зависимость.
