# Общая база описаний и наборов референсов

Основной потребитель — агент внутри сценария StoryArt. Веб, браузер и сервер
для него не нужны: штатный `reference_pool_manager search` уже ищет по новой
базе и возвращает блок `discovery` с описанием, ограничениями и путём обзора.
При `knowledge_status=MISSING/STALE` агент пересобирает базу указанной командой.
Отдельный HTML — необязательный просмотр тех же данных, не этап сценария.

Открываемая таблица: `work/reference-knowledge-20261113/index.html`.
Данные: `DATABASE.json` и `references.sqlite3` в той же папке. Это локальный,
воспроизводимый слой поиска по всем текущим записям пяти дополнительных пулов
и принятому одиночному набору SODABABYX. Архивы отвергнутых генераций не читаются.
Источники identity и STYLE продолжают разрешаться своими штатными менеджерами.

## Сборка на новом checkout и после обновления

Каталоги других пулов и новый SODABABYX приходят из Git. Сначала установить
текстовые метаданные (без скачивания изображений), затем построить базу:

```powershell
.\scripts\storyart.ps1 reference_packs metadata --all
```

```powershell
.\scripts\storyart.ps1 reference_knowledge build
```

Оба шага выполняет `scripts/update-references.ps1` без параметров. Для явной
установки остальных изображений используется `-All`; недостающие вырезки
восстанавливаются из своей копии через `-FromDir`. Источники, зависимости и
ограничения полной установки: [REFERENCE_INSTALLATION.md](REFERENCE_INSTALLATION.md).

Результаты сборки — DATABASE.json, SQLite, HTML и коллажи в указанном выше
локальном каталоге. Если необязательные картинки не установлены, их карточки
остаются текстовыми; SODABABYX уже доступен из Git. Пересобрать после `git pull`,
установки изображений, изменений метаданных и при `MISSING`/`STALE`.
Изменённые хеши источников не принимаются автоматически. Старые пользовательские
наборы кандидатов тоже нужно сравнить с актуальными входами.

## Сначала понять задачу, затем смотреть

1. Из буквального ТЗ выделить, **что требуется получить от референса**:
   форма тела/части, посадка одежды, поза/опора, камера, жест, одежда или учебный
   вопрос. Зафиксировать пол персонажа, ракурс и неизменяемые параметры.
   Само наличие базы не разрешает поиск необязательных референсов без запроса.
2. Выполнить `reference_knowledge overview`: прочитать компактную общую таблицу
   библиотек, их содержимого и ограничений. Затем `search` по узкой теме и полу.
   В выдаче есть содержательное описание, его основание и недостающие проверки.
   Не читать DATABASE.json целиком и не открывать подряд все изображения.
3. Из подходящих описаний выбрать тему/обзор. Коллажи имеют номер ячейки,
   точный ID и хеш. Они только для поиска; не прикреплять коллаж к генератору.
   `show --key` возвращает полную карточку и путь конкретного оригинала, когда
   субъект и текущая привязка позволяют просмотр. Просмотреть выбранный оригинал
   в полном разрешении. Для неизвестных меток доступны только метаданные;
   не определять пол по имени, тегам или соседней карточке.
4. Сопоставить **этот** оригинал с **этим** ТЗ: что видно и скрыто, нужный ли
   ракурс, та ли анатомическая сторона, согласованы ли суставы/таз/торс/опоры,
   можно ли использовать нужную посадку без переноса чужого тела/стиля.
   Записать конкретное «подходит потому что…» и несовпадения. Несовпадение
   обязательного признака означает выбор другого кандидата, а не ослабление ТЗ.
5. Собрать список через UI или `set`. Набор сохраняет причину выбора,
   SHA256 и открытые проверки. `CANDIDATES_NOT_APPROVED`, `NOT_CHECKED` и
   `attachment_allowed=false` намеренны: экспорт не является приёмкой.
6. Выполнить существующий `reference_pool_manager select`, для SODA — штатный
   выбор точного варианта, далее `prepare-generation` и exact-call validation.
   Принятие коллекции не отменяет пол, роль, права и индивидуальную применимость.
   Повторно не смотреть уже проверенный неизменённый источник в той же роли
   и при эквивалентном ТЗ; сохранить хеш и конкретное доказательство проверки.

## Команды

```powershell
.\scripts\storyart.ps1 reference_knowledge overview
```

```powershell
.\scripts\storyart.ps1 reference_knowledge search --query "меч" --pool PINTEREST_SKETCH --subject MALE --limit 8
```

```powershell
.\scripts\storyart.ps1 reference_knowledge search --query "торс" --pool SODABABYX_SINGLE --subject FEMALE
```

```powershell
.\scripts\storyart.ps1 reference_knowledge show --key "SODABABYX_SINGLE:SODA_HWss9-yWIAALWyJ__01_PETITE"
```

```powershell
.\scripts\storyart.ps1 reference_knowledge set --key "SODABABYX_SINGLE:SODA_HWss9-yWIAALWyJ__01_PETITE" --brief "Проверить форму торса под буквальное ТЗ текущего кадра" --output work/reference-candidates.json
```

`--key` можно повторять. Указывать только реально выбранные ID. Поле причины
заполняет агент после сравнения с ТЗ. Команда не делает визуальную проверку.

Для локального просмотра используется `serve_reference_knowledge` на loopback;
он выдаёт только страницу, её коллажи и явный список проверенных изображений,
не открывает каталоги и остальные файлы проекта. После пересборки изменённых
изображений перезапустить только этот просмотрщик. Сам HTML также открывается
обычным браузером как локальный файл; если среда запрещает `file:`, использовать
разрешённый HTTP-просмотр приложения.

```powershell
.\scripts\storyart.ps1 serve_reference_knowledge --port 18841
```

```powershell
.\scripts\storyart.ps1 reference_knowledge build
```

Сборщик использует только зарегистрированные manifests и существующие
наблюдения, добавляет понятные области применения, ограничения, русские
поисковые синонимы и основания описаний. Не сочиняет невидимые части тела,
посадку или ракурс. Недостающие данные отмечены явно. Пересборка нужна после
изменения источников/описаний; CLI проверяет хеши входных manifests и кода.
HTML — снимок базы; актуальность перед использованием проверяется CLI.
Изменённый выбранный файл блокирует экспорт через CLI до пересборки.

## Охват и обзоры

У каждой записи есть описание даже при запрете визуального открытия.
Подтверждённые источники с совпадающим текущим хешем получают тематические
обзоры с раздельными метками субъекта. Для одежды, учебных материалов и
части поз отсутствующие метки не подменяются: такие записи остаются текстовыми.
Существующий принятый альбом SODABABYX и его нейтральные схемы сохраняются;
общая база не расширяет разрешения нейтральных схем для генерации.

SQLite хранит `refs` (ключ, пул, субъект, описание, JSON карточки) и FTS5
`search` (ключ и поисковый текст). Ключ `POOL:ID` уникален; родительский лист
и его одиночники связаны через `group`, не считаются независимыми свидетельствами.
Оригиналы, source manifests и существующие генерационные допуски не меняются.

Индивидуальные визуальные описания 182 доступных Pinterest-эскизов хранятся в
`config/reference_knowledge_descriptions.json`: точный source hash,
обзорный лист, номер ячейки и наблюдение. Сборщик отвергает устаревшую привязку.
Если исторический обзорный лист не установлен, это явно отмечено в карточке;
изменившийся доступный лист отклоняется по хешу. Эти описания уточняют действие, положение тела, опоры и обрезанные области,
но не утверждают анатомическую корректность по уменьшенному обзору.

## Явно делегированный выбор

Когда пользователь прямо поручает выбрать всё самостоятельно, сценарий может
использовать `startup_selection_mode=DELEGATED` и `delegated_selection_json`.
Это отдельный источник решений: точная цитата пользователя сохраняется без
добавленных процентов, а пять решений и причина записываются как решения агента.
Receipt содержит request_id, current_chat_id, message_id, user_quote, agent_reason
и agent_choices: style, character, fidelity, aux_body_decision, reference_policy.
Поддерживаются полные формулировки «Выбери всё самостоятельно»,
«Choose everything yourself» либо полный запрос генерации с отдельным
«полностью сам». Частичное делегирование («выбери позу полностью сам»), молчание,
обычное «да» и ограничивающие условия не разрешают этот режим; не переписывать
цитату под распознаватель. Root обязан проверить исходное поручение и сохранить
все его ограничения, включая переданные из родительского чата. При переносе
сохранить исходные source_chat_id/source_message_id в receipt дополнительно
к ID текущего сообщения передачи. Меню не выдумывается. Повторная подготовка
использует тот же DELEGATED receipt в том же запросе; REUSE не расширен.
Режим не разрешает изменение профиля, допуск источников, обход exact validation
или работу за пределами поручения. Поле selected_by=AGENT уточняет совместимое
историческое поле user_selected_percentage в плане.

Если выбор стиля изменил штатную папку незапущенного запроса, использовать task_execution_guard relocate-preparation --state <собственный guard> --destination <STYLE_GENERATIONS/00_PENDING/тот_же_request_id>. Только до plan/call/attempts; команда сохраняет историю и binding. Не переносить такую папку вручную и не редактировать реестр.
